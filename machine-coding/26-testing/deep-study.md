# Testing Machine-Coded UI

## Why it matters
Test behavior and state transitions. Cover component/integration tests, async behavior, network boundaries, loading/error/empty/race/cancellation states and accessibility. Challenge: add tests to one flagship component and explain what you deliberately do not test.

## Completion contract
You are complete only when you can explain the requirements, component/state design, implementation, failure modes, accessibility, performance and testing strategy without notes.

## Interview follow-ups
- What would you change if time were cut in half?
- What breaks under concurrency?
- What would you measure?
- How would you scale the feature?

## Practical output
Commit the solution or interview notes and record the next improvement.
