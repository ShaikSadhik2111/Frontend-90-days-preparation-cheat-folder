# Machine Coding — Interview-Ready Curriculum

This is a **build-practice track**, not a list of UI components. The goal is to repeatedly turn requirements into a working, accessible, testable and performant vertical slice under interview time constraints.

## Learning contract

Every problem follows:

**Clarify → Requirements → Component tree → State ownership → Data/API model → Vertical slice → UI states → Edge cases → Accessibility → Concurrency → Performance → Tests → Trade-offs → Interview follow-ups**

A solution is not complete because the happy path works.

## Mastery levels

**Level 1:** happy path  
**Level 2:** loading/empty/error + edge cases  
**Level 3:** accessibility + tests  
**Level 4:** concurrency + caching + performance  
**Level 5:** architecture, trade-offs and spoken explanation under pressure

## Flagship set

Autocomplete, data grid, Kanban, file upload, chat, multi-step form, command palette and virtualized feed. Solve representative problems deeply rather than trying to memorize every possible UI.

## Timed protocol

For a 45-minute problem:

- 0–5 min: clarify and acceptance criteria
- 5–10 min: component/state/data design
- 10–35 min: vertical slice
- 35–40 min: edge/accessibility/concurrency
- 40–45 min: tests, trade-offs and explanation

If time is cut, preserve the vertical slice and explicitly state what you would add next.
