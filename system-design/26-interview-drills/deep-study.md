# Interview Drills — Deep Practice

## Purpose
Turn the system-design curriculum into spoken decision-making under time pressure.

## 10-minute drill
Clarify the user, one critical workflow, two constraints and the most important failure mode. Give a simple architecture and one trade-off.

## 30-minute drill
Requirements → assumptions → scale estimate → architecture → state ownership → API/data flow → caching → failure/recovery → security/accessibility → performance → observability → trade-offs.

## 45-minute drill
Add one hard follow-up: offline, 10× scale, realtime collaboration, strict consistency, partial outage, slow device or security incident.

## Unknown-problem protocol
Do not search for a memorized diagram. Start from constraints. Choose the smallest architecture that satisfies them, then evolve it when the interviewer changes a requirement.

## Final case set
Design a large-data dashboard, a realtime collaboration surface and a search/autocomplete platform.

## Completion
You can defend every major boundary, identify what can be stale, explain what happens when dependencies fail, and describe what you would measure in production.
